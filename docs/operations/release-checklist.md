## 1. 发布前

- [ ] 目标分支 CI 全绿（后端测试、前端单测、构建、E2E、安全测试）。
- [ ] .env.staging 中的密码与密钥已更新，且未提交到仓库。
- [ ] 已确认当前线上 APP_IMAGE_TAG，记录为回滚点。
- [ ] 已执行一次数据库备份并校验 SHA-256。
- [ ] 已评估本次 Flyway 迁移是否向下兼容（新增列/表优先，避免删改）。

## 2. 发布

- [ ] docker compose ... up -d 使用新 APP_IMAGE_TAG。
- [ ] 等待 app healthcheck 通过，nginx healthcheck 通过。
- [ ] 确认 MySQL 未被公网暴露。

## 3. 发布后验证

- [ ] https://<host>/ 返回 200 且 SPA 可加载。
- [ ] https://<host>/api/v1/resources 返回 success:true。
- [ ] 注册 -> 登录 -> 刷新 -> 退出 正常。
- [ ] 资源收藏、论坛发帖/评论/点赞/收藏 正常。
- [ ] 个人资料保存与密码修改 正常。
- [ ] 浏览器控制台无 4xx/5xx 异常，无未处理 rejection。
- [ ] 移动端 375px 无横向滚动。

## 4. 回滚触发条件

满足任一条件即回滚：

- 核心流程（登录、资源、论坛）任一不可用超过 5 分钟。
- 错误率持续 > 5%。
- 数据库迁移导致旧数据不可读。

## 5. 回滚步骤

- [ ] APP_IMAGE_TAG=<previous_tag> docker compose ... up -d。
- [ ] 确认 healthcheck 通过。
- [ ] 重跑第 3 节关键验证。
- [ ] 记录故障时间线、影响范围与根因。
